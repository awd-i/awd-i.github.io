Can a Copy Head Help Image Editing Models?

Aidan Whitedeer - Nov, 23, 2026

Draft.

TL;DR

This post explores Copy-Paste Language Models (CPLMs), which give a language model a second route to its output: a pointer that can paste a token straight from the context, mixed with the usual output head by a learned gate. I ask whether a copy head added after training could help discrete-token image models. Plain image generation trivially has almost nothing to copy, so I look at image editing, where most tokens repeat the source. There, the editing model already copies its source through ordinary attention, so a pointer has little to add.

Introduction

This past quarter, I’ve been taking a class called CS 312, where we learn deep learning through running empirical experiments on different properties of ML systems.

On one of my more recent course assignments, one technique that really caught my eye was Copy-Paste Language Models (CPLMs) (Godey & Artzi, 2026a)1. I thought the method was pretty intuitive, and the architecture behind it was very interesting.

In our class experiments, we found that on d8 models (8 blocks, width 512, about 35M parameters), that CPLM surprisingly effective at making models more expressive.

The reason this occurs is because it bypasses the rank limit of the output head. Past literature states that a standard softmax head with hidden size d can only produce next-token log-probabilities of rank at most d. This is called the softmax bottleneck of Yang et al. (2018)2, which Godey et al. (2024)10 link to performance saturation in small LMs. With a rank r head, our limit is r, however as we come to find out, the copy path is not subject to that constraint.

How does CPLM work?

CPLM belongs to the family of pointer and copy mechanisms (Vinyals et al., 2015; Gu et al., 2016; See et al., 2017; Merity et al., 2017)3–6. At an abstract level, the idea of these mechanisms is to give the model a second route to the output. CPLM adds a “copy pointer”, which is directed to a position in the context. The model can then paste a token from that location, on top of scoring every vocabulary item through the output head, which ends up giving us a more expressive probability distribution.

Overview of Class Experiments (d8)

Say we have a base LM with hidden state ht at position t:

Output head
pgen(y | x≤t) = softmax(Wo ht)y

We then build a copy pointer: the current hidden state (our context) becomes a “query” and the hidden states at past positions become “keys”, along with one extra learned “sink” key. We then match and softmax them together to get a “copy probability” for each position. In essence, we are essentially running a single attention head over earlier positions:

Score for position i
st,i = (Wq ht)⊤ (Wk hi) / √d
Score for the sink
st,∅ = (Wq ht)⊤ k∅ / √d
Copy weight
at,i = exp(st,i)exp(st,∅) + Σj≤t exp(st,j)
Sink weight
at,∅ = exp(st,∅)exp(st,∅) + Σj≤t exp(st,j)

Pointing at position i means “paste the token at i”, so the copy distribution over the vocabulary sums the pointer’s weight over every occurrence of a token:

Copy distribution
mt(y) = Σi≤t : xi=y at,i

The sink is the pointer’s way of saying “nothing here is worth copying”: whatever weight it puts on the sink (at,∅) is handed back to the normal output head.

A gate then decides how much to trust the pointer. Instead of a separate module, the gate is one extra <copy> option added to the output softmax, and its probability is the gate:

Gate
ct = softmaxvocabulary ∪ {<copy>}(output logits)<copy>

Using the gate and the sink, we create a final next-token distribution using the mixture:

Mixture
p(y) = (1 − ct + ct · at,∅) · pgen(y) + ct · mt(y)

Equivalently, the copy head gets an effective weight of λt = ct(1 − at,∅) and the output head gets the rest. This is the gate/sink design from Godey & Artzi (2026a)1.

Why does it work?

CPLM is effective because a softmax head of rank r can only produce log-probability matrices of rank at most r (Yang et al., 2018)2. Using the copy term, the probability can be placed directly onto context tokens without going through Wo, so we're not limited to a rank-r head's expressiveness. This also predicts that the copy head should help more as the head gets narrower.

My rank sweep tests this directly. CPLM beat plain softmax at every head rank, by 0.021 nats at full rank and by up to 0.122 nats at rank 32 on my d8 model, roughly a sixfold larger gain at the narrowest head.

We can also see that the LM head is also a bottleneck for gradients. Since the training signal reaching the backbone is compressed through the head (Godey & Artzi, 2026b)9. This means that the copy head also gives a gives the backbone a second gradient path that avoids it.

From Text to Image Tokens

After seeing these results in pre-training, as well as reading the paper, I got curious about where else a copy head could be useful. For a pointer to help, two things have to be true.

First, there has to be something to copy. The head can only gain on tokens that are already in the context. Text has plenty of them: in my d8 validation data, 49% of positions were tokens already in the context.

Second, the model must not already be copying well on its own. Models track when something is about to be repeated without any pointer: ordinary attention looks back at earlier occurrences, the behaviour attributed to induction heads (Olsson et al., 2022)7. A pointer only adds something where the output head fails to turn that signal into a confident prediction.

I was also interested in adding the head to a model that has already been trained, since I did not have the compute to pre-train one with the head built in. There is precedent for this: Chang et al. (2023)8 added pointer-style heads to pretrained GPT-2, T5, and BART models, continued training, and reported gains. The CPLM paper itself is more cautious. Godey & Artzi (2026a, Section 4.1)1 attribute most of the benefit to the gradients the copy head sends into the backbone during training, and argue in Section 5 that a head added after pretraining "cannot fully undo" the effect of the standard head's bottleneck (Godey & Artzi, 2026b)9. So a late head is only worth training where the possible gain is large, which gave me a hypothesis I could check before training anything:

A copy head could help a discrete-token image model wherever many of its next tokens already appear in the context and the model does not already predict them well.

Image Model Experimentation

If a copy head helped text transformers, I hypothesized that it could potentially help discrete-token image models too. Models such as LlamaGen11, Emu312, Chameleon17 and Janus-Pro18 predict the next image token from a fixed codebook, the same way a language model predicts the next word. Adding the head fit them without making any architecture changes.

Trivially, we know it will fail for plain image generation. A copy head can only gain on tokens that already appear in the context, and a 256-token image from LlamaGen's tokenizer (16,384 codes) uses about 250 different codes, so only 2% of next tokens could be copied. Editing is where I was curious, since most of an edited image is identical to its source. To check, I tokenised image pairs with the same tokenizer and counted how often the tokens repeat (Figure 1).

Editing is the exception. Most of an edited image is identical to its source, and so are its tokens, which puts the share at 61%, in the same range as text. So a copy head could help an image model that edits. Video does only a little better than plain generation for the next frame, and the reason is that the tokenizer is noisy: shifting an image by a single pixel changes more than a third of its codes, so two nearly identical frames mostly get different tokens.

One caveat with these results is that the match rate depended on how the dataset was built. On some datasets, an image was only changed in one region, and the rest of its tokens survived, which meant CPLM pointers were useful here. When both images were generated, the "unchanged" parts are regenerated and almost none of the past tokens matched, which meant that the pointers weren't useful. No large dataset came close to MagicBrush, and only one slice of OmniEdit cleared the 30%.

The tokenizer matters is as important as the data, Emu3's tokenizer uses 4,096 tokens per image and is far more sensitive than LlamaGen's: shifting an image by one pixel leaves only 5% of its codes unchanged, and only 3% of a video frame's tokens match the previous frame. On MagicBrush edit pairs, 37% of tokens match the source, well below the share with LlamaGen's tokenizer. Which meant that editing is still the one setting that cleared the bar, but by a smaller margin on the larger model's tokenizer.

Formulating another experiment: An ordinary attention layer can also copy the token at the same position, and if the editing model already does that well, a pointer has nothing to add. So I decided to do another test, on EditAR22, a public 775M-parameter editing model built on LlamaGen. It reads the source image's 1,024 tokens, then the instruction, then writes the edited image's 1,024 tokens, so the tokens worth copying are already in its context. With no training, I counted how many edited-image tokens equal the source token at the same position, and measured how much loss EditAR still has on exactly those tokens. That product is the most a perfect pointer could gain, and only if it was large would I go on to train a head on PIPE23, a set EditAR was itself trained on.

The editing model already copies. The pass mark is missed on every set, so I did not train a head. The token counts held up: most edited tokens match the source on PIPE and MagicBrush, as I predicted. What I got wrong was the model. I expected 1 to 3 nats of loss left on those tokens, and it is a small fraction of that, because EditAR already ranks the source token first almost every time. Where an edit did change a token, EditAR still gives the old source token 45% of the probability, so a copy head would push it further in the wrong direction. So the hypothesis fails for editing too: an editing model that can see its source already copies well through ordinary attention. This result is narrow: it is one editing model, trained with the source in its context, and an upper bound computed from scored tokens, since I did not train a head on it or generate edits.
